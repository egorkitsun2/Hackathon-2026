# Запуск с backend Егора

Открывайте сайт через backend на **http://localhost:8787**. Live Server и
`python -m http.server` не обслуживают API и не подходят для проверки входа.

В терминале PowerShell из корня репозитория:

```powershell
$env:FRONTEND_DIR = (Resolve-Path ./frontend).Path
$env:APP_ORIGIN = 'http://localhost:8787'
cd backend
npm.cmd ci
# Только для первой подготовки пустой базы:
npm.cmd run seed
npm.cmd run dev
```

Seed создаёт два аккаунта сотрудника и один администратора. Телефоны и случайные
пароли находятся в `backend/.local/test-accounts.json`. Откройте этот файл локально
и используйте аккаунт с `role: "employee"`. Не публикуйте файл с паролями.
При уже созданных аккаунтах повторно запускать seed не нужно.

Настоящие вход, проверка сессии после перезагрузки, выход и список своих обращений
и создание обращений подключены. Роль берётся из ответа backend.

Для просмотра очереди войдите аккаунтом с `role: "admin"` из того же локального
файла тестовых аккаунтов. Администратору доступны список всех обращений, фильтр
по статусу, пагинация и подробный просмотр с данными автора. Фильтр и страница
сохраняются при возврате из деталей и сбрасываются при выходе. На компьютере
показывается таблица, на телефоне — карточки. Изменение статуса добавим следующим
шагом; на этом этапе очередь и детали доступны для чтения.

После входа сотрудником нажмите «Создать обращение», выберите тип и заполните
тему и описание. После отправки сервер вернёт номер обращения; ссылка
«Перейти к моим обращениям» открывает обновлённый список. При сетевом сбое
проверьте список перед повторной отправкой: ответ мог потеряться после сохранения.

«Подробнее» в списке или после отправки открывает описание, статус, ответ
администрации и историю. Прямая ссылка имеет вид `#/tickets/1` и работает после
перезагрузки с действующей сессией. Чужое или отсутствующее обращение показывает
сообщение о недоступности. Назад можно вернуться ссылкой или кнопкой браузера.

Проверки frontend из корня репозитория:

```powershell
node --test frontend/tests/*.test.mjs
```

Интеграционная проверка с настоящим backend использует SQLite в памяти,
не изменяя локальную базу и аккаунты. При установленных зависимостях backend:

```powershell
cd backend
node --import tsx ../frontend/tests/create-ticket.integration.mjs
```
