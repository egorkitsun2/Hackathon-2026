# Запуск с backend Егора

После исправлений аудита: список сотрудника сохраняет страницу при возврате
из деталей; старые запросы не завершают новый вход. В окне сброса пароля можно
отменить ожидание, максимальное ожидание — 30 секунд; при неизвестном результате
повторный сброс требует подтверждения. Лимит входов на номер считает неверные
пароли, а оставшееся время приходит в Retry-After и отображается обратным отсчётом.
Общий защитный лимит по IP сохранён. Для новой политики перезапустите backend;
старые счётчики в базе не очищаются автоматически при обновлении.

Сброс пароля: администратор → «Сотрудники» → «Сбросить пароль» → проверить
имя и телефон → «Подтвердить сброс». Отправляется один POST с `{}`; строка
обновляется из ответа сервера. Временный пароль показывается один раз,
копируется только по кнопке; при отказе буфера его можно выделить вручную.
При закрытии окна, переходе или выходе пароль удаляется из DOM и памяти
состояния интерфейса. Пароль не сохраняется в браузерных хранилищах или отчётах.

Сброс отзывает старые сессии и требует смены временного пароля при входе.
Заблокированный аккаунт нужно активировать отдельно. При потере ответа
автоматического повтора нет; новый сброс требует нового подтверждения.
Конфликт `PASSWORD_CHANGED` при сбросе обновляет список сотрудников и не
завершает сессию администратора.

Браузерная проверка сброса (при установленном тестовом Firefox/Playwright)
из backend: `node --import tsx ../frontend/qa/password-reset-browser.mjs`,
с `PLAYWRIGHT_BROWSERS_PATH`, указывающим на `frontend/.cache/ms-playwright`.
Тест использует базу в памяти и искусственные аккаунты; снимки результата
с временным паролем не сохраняются.

Открывайте сайт через backend на **http://localhost:8787**. Live Server и
`python -m http.server` не обслуживают API и не подходят для проверки входа.

В терминале PowerShell из корня репозитория:

```powershell
$env:FRONTEND_DIR = (Resolve-Path ./frontend).Path
$env:APP_ORIGIN = 'http://localhost:8787'
cd backend
npm.cmd ci
# Только для первой подготовки пустой базы:
npm.cmd run seed
npm.cmd run dev
```

Seed создаёт два аккаунта сотрудника и один администратора. Телефоны и случайные
пароли находятся в `backend/.local/test-accounts.json`. Откройте этот файл локально
и используйте аккаунт с `role: "employee"`. Не публикуйте файл с паролями.
При уже созданных аккаунтах повторно запускать seed не нужно.

Настоящие вход, проверка сессии после перезагрузки, выход и список своих обращений
и создание обращений подключены. Роль берётся из ответа backend.

Для просмотра очереди войдите аккаунтом с `role: "admin"` из того же локального
файла тестовых аккаунтов. Администратору доступны список всех обращений, фильтр
по статусу, пагинация и подробный просмотр с данными автора. Фильтр и страница
сохраняются при возврате из деталей и сбрасываются при выходе. На компьютере
показывается таблица, на телефоне — карточки.

В деталях нового обращения нажмите «Взять на рассмотрение». Затем выберите
«Решить» или «Отклонить», введите обязательный комментарий 5–2000 символов и
нажмите «Сохранить решение». После ответа API статус, ответ и история
перезагружаются с сервера. Закрытые обращения доступны только для просмотра.
При конфликте статусов загружается актуальное состояние; при потере ответа
запрос изменения не повторяется автоматически. Комментарий сохраняется при
смене языка и очищается после успешного сохранения либо выхода из деталей.

В панели администратора ссылка «Сотрудники» открывает `#/admin/users`: список,
создание, блокировка и активация аккаунтов. ФИО, отдел и должность — 1–120
символов. Роль сотрудника и временный пароль назначает сервер. После создания
передайте показанные телефон и пароль лично сотруднику. Результат отображается
однократно и очищается при закрытии, переходе или выходе; пароли не сохраняются
в хранилище браузера. При потере ответа создания список обновляется, но повторить
получение временного пароля или сбросить пароль через сайт пока нельзя.

Для нового сотрудника вход и восстановление сессии читают заголовок
`X-Password-Change-Required`. До смены пароля любые ссылки ведут на
`#/change-password`, запросы обращений не отправляются. Требуются текущий пароль,
новый (12–128 Unicode-символов, до 1024 UTF-8 байт) и его повтор. Пароли не
обрезаются. После успеха открывается кабинет; cookie обновляет сервер.
Блокировка отзывает сессии сотрудника; после активации нужно войти заново.
Существующие тестовые аккаунты могут не требовать смены пароля — проверяйте
этот сценарий на новом сотруднике. Все новые экраны доступны на РУС / ҚАЗ.

После входа сотрудником нажмите «Создать обращение», выберите тип и заполните
тему и описание. После отправки сервер вернёт номер обращения; ссылка
«Перейти к моим обращениям» открывает обновлённый список. При сетевом сбое
проверьте список перед повторной отправкой: ответ мог потеряться после сохранения.

«Подробнее» в списке или после отправки открывает описание, статус, ответ
администрации и историю. Прямая ссылка имеет вид `#/tickets/1` и работает после
перезагрузки с действующей сессией. Чужое или отсутствующее обращение показывает
сообщение о недоступности. Назад можно вернуться ссылкой или кнопкой браузера.

Проверки frontend из корня репозитория:

```powershell
node --test frontend/tests/*.test.mjs
```

Интеграционная проверка с настоящим backend использует SQLite в памяти,
не изменяя локальную базу и аккаунты. При установленных зависимостях backend:

```powershell
cd backend
node --import tsx ../frontend/tests/create-ticket.integration.mjs
```

Интеграционный сценарий также проверяет создание сотрудника, обязательную смену
пароля, отзыв старых сессий, создание обращения, блокировку и повторный вход
после активации. Это проверка API с реальным backend; визуальный браузерный тест
в эту команду не входит.
