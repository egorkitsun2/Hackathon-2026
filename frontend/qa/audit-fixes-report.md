# Исправления по итоговому аудиту — 11 ноября 2026

## Вердикт

Все четыре запрошенные проблемы исправлены и проверены отдельными сценариями.
71 тест frontend и 39 тестов backend прошли, TypeScript без ошибок.
Проверки выполнялись на изолированных базах; основная база и её лимиты
не изменялись. Коммитов и push не выполнялось.

## F1: ложный выход — исправлено

API запоминает поколение сессии при отправке запроса. Начало входа/выхода,
окончание сессии и успешная смена пароля инвалидируют предыдущие запросы.
Их запоздавшие ошибки авторизации не вызывают глобальный выход/смену пароля
в новом сеансе. Собственные ошибки актуальной сессии по-прежнему обрабатываются.

Firefox: задержанный 401 от списка сотрудника освобождён после входа admin.
Admin остался на панели, auth/me вернул 200. Проверено на 1280 и 390 px.
Дополнительно — API unit test старого и актуального 401.

## F2: зависший reset — исправлено

Кнопка отмены и Escape позволяют прекратить ожидание. AbortController
ограничивает ожидание 30 секундами. При отмене/тайм-ауте секрет очищается,
окно закрывается, отображается «результат неизвестен». Сервер уже мог
изменить пароль, поэтому POST не повторяется; нужен новый явный сброс.
Поздний ответ не восстанавливает секрет или состояние новой операции.

Firefox: зависший запрос → Escape → интерфейс доступен; новый явно
подтверждённый зависший запрос → 30-секундный тайм-аут → окно закрыто.
Количество запросов ровно 2 для двух подтверждений, автоматических повторов нет.
Проверено на 1280/390 px, дополнительно unit test тайм-аута и позднего ответа.

## F3: потеря страницы — исправлено

Страница списка сотрудника сохраняется при переходах в детали/назад.
При выходе и смене сотрудника сбрасывается. Если последней страницы уже нет,
запрашивается последняя существующая страница.

Firefox: страница 2 → детали → назад → страница 2, на 1280/390 px.
Unit test отдельно проверяет выход и смену аккаунта.

## F4: лимит и остаток времени — исправлено

Точечно изменены backend/src/security.ts, backend/src/index.ts,
backend/tests/api.test.ts и описание политики в backend/README.md и
docs/api-contract.md. Схема БД и сохранённые аккаунты не менялись.

- Телефонный лимит входа теперь считает только неверные пароли: 5 за 15 минут.
  Успешные входы не расходуют его и не обнуляют прежние ошибки.
- Общий лимит 60 попыток на IP перед хешированием сохранён: успешные запросы
  продолжают расходовать этот защитный бюджет.
- Лимит работы change-password не ослаблялся.
- Retry-After вычисляется по остаткам окон блокирующих счётчиков, а не всегда 900.
- Frontend показывает mm:ss, обновляет его раз в секунду, разрешает повтор
  в нуле. Переход к другому номеру не запирается локальным таймером первого;
  сервер продолжает независимо проверять оба лимита.

Backend test: 6 успешных входов разрешены; после 5 неверных паролей запрос
с верным паролем получает 429; искусственно состаренное окно отдаёт около
30 секунд; после истечения окна вход снова разрешён. Отдельно подтверждён
лимит IP и его остаток около 20 секунд.

Firefox: смоделированный Retry-After: 3 → 00:03 → 00:01 → кнопка активна
в нуле. Реальная логика backend проверена API-тестами, без ожидания 15 минут.

Существующие счётчики основной базы не очищались: старые блокировки истекут
естественно. После установки изменений нужно перезапустить backend.
