# Проверка вложений в Firefox — 11 ноября 2026

Результат: PASS на ширине 1280 и 390 px. Исходная проблема пользователя
на свежей странице с текущими файлами проекта не воспроизведена.

## Условия

- Официальный Playwright и его тестовый Firefox, без расширений личного браузера.
- Только HTTP localhost (127.0.0.1), отдельный случайный порт при каждом запуске.
- SQLite :memory:, два искусственных аккаунта со случайным паролем в памяти.
- Отдельная приватная папка вложений в системной временной директории;
  после теста удалена. Сервер и Firefox остановлены.
- Основная база, реальные пароли и аккаунты не использовались.
- Внешние запросы браузера заблокированы.

## Что выполнено в браузере

1. Вход сотрудником через обычную форму.
2. Заполнение нового обращения и выбор `фото.pdf` до отправки.
3. Нажатие «Отправить обращение»: создание и POST вложения, ответ 201.
4. Результат: «Вложения загружены. Загружено файлов: 1/1».
5. В деталях сотрудника файл отображается: имя, application/pdf, размер, Скачать.
6. Скачивание через интерфейс: имя совпадает, содержимое побайтно совпадает.
7. Перезагрузка: вложение по-прежнему отображается.
8. Выход, вход администратором, открытие того же обращения из очереди.
9. Вложение отображается, скачивание возвращает те же байты.
10. Мобильная ширина 390 px: весь сценарий повторён, горизонтального
    переполнения страницы в проверенной карточке нет.

Ошибок JavaScript не зарегистрировано. Основной PDF — искусственный тестовый
файл 51 байт, исходный проблемный файл пользователя не предоставлен.

Первый запуск тестового стенда был отклонён защитой backend: приватное
хранилище нельзя располагать внутри frontend. Тестовая конфигурация исправлена
на отдельную папку вне frontend; продуктовый backend не изменялся.

## Вывод и ограничения

Текущая связка frontend/backend успешно обрабатывает загрузку, показ и
скачивание обеими ролями в настоящем Firefox. Ошибка backend, объясняющая
исходный отказ пользователя, не доказана. Ранее read-only проверка основной
базы показала 0 вложений у обращений 7–9: у них не было сохранённого файла.

Кэш, расширения личного браузера, содержимое исходного файла и конкретный
неудачный запрос пользователя этим прогоном не проверялись. Для точной причины
нужен исходный файл или статус/код его неудачного POST, либо воспроизведение
со свежей страницей текущей версии. Доступ к личному Firefox не получен.
