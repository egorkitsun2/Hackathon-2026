## Подтверждённые дефекты

### F1 — средняя серьёзность: запоздавший 401 завершает новый вход

Место: frontend/js/api.js:22 и frontend/js/app.js:174.

Воспроизведение в Firefox:

1. Войти сотрудником, задержать ответ списка обращений.
2. Выйти и войти администратором.
3. Освободить старый ответ сотрудника с 401 UNAUTHORIZED.
4. Интерфейс переводит администратора на login, хотя auth/me с действующей
   admin-cookie всё ещё возвращает 200. После перезагрузки admin восстанавливается.

Причина: общий API-слой отправляет session-ended независимо от поколения
сессии запроса. Защита requestId в экранах срабатывает уже после глобального
события и не предотвращает ложный выход. Смена роли/чтение чужих данных не
обнаружены; подтверждено ошибочное завершение интерфейсной сессии.

Исправление: привязать события авторизации к поколению сессии на момент
отправки запроса, отменять старые запросы при выходе. Старый ответ не должен
менять состояние новой авторизации. Нужен регрессионный тест этой гонки.

### F2 — средняя серьёзность: зависший reset блокирует интерфейс

Место: frontend/js/accounts.js:95, 240–241 и frontend/js/api.js:2.

Воспроизведение: в Firefox задержать POST reset-password без ответа. Кнопка
закрытия отключена, Escape отменяется, модальное окно перекрывает logout
и переходы. Клиентский тайм-аут отсутствует; пользователь ждёт сетевого
тайм-аута браузера или перезагружает страницу.

Исправление: ограниченное ожидание через AbortController, безопасный выход из
ожидания с сообщением «результат неизвестен». Сервер мог уже изменить пароль,
поэтому нельзя автоматически повторять reset. Повтор — с новым подтверждением.
Секрет не должен появляться в закрытом окне после позднего ответа.

### F3 — низкая серьёзность: теряется страница списка сотрудника

Место: frontend/js/employee.js:74–76.

Воспроизведение: 21 тестовое обращение → страница 2 → детали → «Назад к
обращениям». Открывается страница 1. openEmployee всегда устанавливает page=1.
У администратора сохранение страницы уже реализовано.

Исправление: сохранять страницу между списком и деталями; сбрасывать её при
смене аккаунта или выходе. При исчезновении последней страницы перейти на
существующую.

## Недочёты и ограничения, отдельно от багов

- Backend считает даже успешные входы в лимит 5 на телефон за 15 минут:
  backend/src/security.ts:22. Это подтверждённая тестами политика, а не потеря
  пароля после перезапуска. Для частого входа и демонстраций она неудобна.
  Менять политику следует согласованно, сохраняя защиту от перебора.
- Backend всегда возвращает Retry-After: 900 при лимите; login frontend выводит
  фиксированные «15 минут», не фактический остаток. Пользователь не видит,
  когда реально можно повторить вход. Для точного счётчика потребуется точный
  Retry-After со стороны API и отсчёт в интерфейсе.
- Переключатель языка не сохраняет выбор после reload; это удобство, не ошибка
  авторизации. Поиск/уведомления — запланированные функции, не дефекты MVP.
- Создание обращения и загрузка файлов — разные операции по текущему API.
  Частичный результат обрабатывается явно, автоматических повторов POST нет.
- Файлы скачиваются защищённо. Антивирусная проверка и встроенный просмотр
  контрактом не предусмотрены; это ограничение продукта.

   экземпляра приложения новый пароль и обновлённая сессия работают, старый
   пароль отклонён. Проверка: qa/password-persistence.mjs.
10. Backend-тесты проверяют права/чужие обращения, Origin, обязательную смену,
    блокировку, квоты и форматы файлов, конкурентные изменения, откаты ошибок БД,
    статистику и административный reset. Сообщения Unexpected API error в
    отрицательных тестах ожидаемы: ошибки БД внедрены намеренно.
