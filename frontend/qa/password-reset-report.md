# Проверка интерфейса сброса пароля

Контракт: docs/frontend-password-reset.md и раздел Reset a forgotten employee
password в docs/api-contract.md. Изменения только frontend.

## Проверки

- Unit/API: подтверждение до POST, тело `{}`, одна отправка при двойном клике,
  обновление карточки данными сервера; отсутствие завершения admin-сессии
  при 409 PASSWORD_CHANGED от reset-password.
- Потеря ответа: список обновляется, POST не повторяется, новый запрос требует
  нового подтверждения. Конфликт и поздний ответ после выхода не восстанавливают
  пароль в интерфейсе.
- Секрет очищается при закрытии, Escape и уходе из раздела; копирование только
  по явной кнопке, при отказе Clipboard API пароль остаётся доступен для
  ручного выделения.
- Реальный Firefox + backend HTTP, SQLite в памяти, случайный порт localhost,
  отдельные вымышленные аккаунты: подтверждение RU/KK, reset 200,
  старая сессия сотрудника получает 401; временный вход открывает прежний
  экран смены пароля, после смены открывается кабинет.
- Заблокированный сотрудник после сброса остаётся заблокированным; окно
  сообщает об отдельной активации. Проверено мобильное окно на 390 px,
  горизонтального переполнения нет. Очистка после выхода проверена.

Скриншоты: 1280-reset-confirm-ru.png, 1280-reset-confirm-kk.png,
1280-reset-blocked-mobile-confirm.png. В них только подтверждение, временных
паролей нет. Журнал этапов и HTTP-статусов: reset-results-1280.json.

Браузер, тестовый сервер и временное хранилище после прогона закрыты/удалены.
Основная база, реальные аккаунты и пароли не использовались. Исходники backend
не менялись. Коммитов и push нет.
