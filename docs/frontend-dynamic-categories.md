# Для Шарапата: динамические направления

Точные запросы, ответы и ошибки: [API v0.6](api-contract.md#v06-dynamic-directions). Прежние API обращений и маршрутизации сохранены, поле category остаётся строковым кодом. Frontend в этой задаче не изменяется.

| Метод / путь (префикс /api/v1) | Назначение |
|---|---|
| GET /categories | Активные коды, прежний `{data:["it","procurement","general"]}` |
| GET /categories?details=true | Активные `{code,name_ru,name_kz,is_active}` |
| GET /categories?details=true&include_archived=true | Все метаданные для подписей в старых обращениях |
| GET /admin/categories | Все направления; каждый объект дополнительно содержит manager_id |
| POST /admin/categories | `{code,name_ru,name_kz,manager_id?}` → 201 `{data:{code,name_ru,name_kz,is_active:true,manager_id}}` |
| PATCH /admin/categories/:code | `{is_active:false}` / `{is_active:true}` → 200 с тем же объектом |
| PATCH /admin/routing/:category | Прежний `{manager_id:ID/null}`, теперь для любого активного направления |

Создание: code — неизменяемый уникальный идентификатор по `^[a-z][a-z0-9_]{1,31}$`; названия RU/KZ обязательны, 1–120 символов после trim. Руководитель необязателен: manager_id=null либо поле отсутствует. Если выбирается ID — только активный manager из существующего списка пользователей. Направление создаётся активным. Названия и код после создания этот этап редактировать не позволяет.

Заменить фиксированный список и словарь названий направлений данными API. В RU использовать name_ru, в KZ — name_kz; code применять только как идентификатор. В форме обращения показывать активные направления. Для старых карточек загружать метаданные с include_archived=true, чтобы архивная категория сохранила подпись. В POST /tickets передавать category=code, assigned_to не отправлять.

У администратора добавить форму создания, показ активных/архивных направлений, действия «Архивировать» и «Восстановить». Для general скрыть архивирование: сервер дополнительно вернёт 409 CATEGORY_REQUIRED_ACTIVE. Перед архивированием пояснить, что новые обращения станут недоступны, а старые обращения, исполнители и история останутся. Изменения — только admin, запросы same-origin с cookie и штатной Origin-проверкой.

Ошибки: 409 CATEGORY_EXISTS — код уже занят, в том числе в архиве; предложить восстановление через PATCH. 409 CATEGORY_ARCHIVED — обновить каталог/форму, не повторять создание обращения автоматически. 404 NOT_FOUND — направление отсутствует. 400 VALIDATION_ERROR — показать поле из details; invalid code=INVALID_CATEGORY_CODE, invalid manager_id=INVALID_MANAGER. 401/403 и PASSWORD_CHANGE_REQUIRED обрабатывать существующим способом.

Архив не должен скрывать старые обращения и кнопки просмотра, истории, вложений, статуса или ручного переназначения. Фильтр needs_reassignment сохраняет прежнее значение; архивирование само по себе не делает назначенного активного руководителя недоступным. Правила архивного направления отображаются, но менять их можно после восстановления. Подписи/подтверждения интерфейса добавить в RU/KZ.
