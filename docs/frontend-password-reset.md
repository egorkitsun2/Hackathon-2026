# ТЗ для Шарапата: сброс пароля сотрудника

Добавить в существующий раздел «Сотрудники» действие «Сбросить пароль». Показывать только вошедшему администратору для employee; API дополнительно проверяет права. Сброс доступен и для заблокированного сотрудника, но не активирует его.

1. Открыть подтверждение с именем и телефоном: прежний пароль и все сессии сотрудника перестанут работать. Не отправлять запрос до подтверждения.
2. Выполнить один `POST /api/v1/admin/users/{id}/reset-password` на текущем origin: cookie через `credentials: 'same-origin'`, `Content-Type: application/json`, тело `{}`. Origin браузер передаст автоматически. На время запроса отключить повторное нажатие; исключить автоматические повторы, в том числе в используемой query-библиотеке.
3. HTTP 200 содержит `data.user` существующего формата employeeView (id, phone, full_name, department, position, role, is_active, must_change_password, created_at) и `data.temporary_password`. Обновить строку сотрудника из data.user. Показать телефон из ответа, временный пароль и кнопку «Копировать».
4. Текст предупреждения: **«Пароль будет показан только один раз. Передай его сотруднику лично»**. Для заблокированного аккаунта дополнительно сообщить, что необходима отдельная активация.
5. Держать пароль только в памяти открытого окна. При закрытии окна, переходе со страницы или выходе из аккаунта очистить его и mutation/query cache. Не сохранять в localStorage, sessionStorage, URL, логах, аналитике, отчётах ошибок и кэше запросов. Копирование выполнять только по нажатию; при ошибке Clipboard API оставить возможность ручного выделения.
6. При сетевой ошибке или потере ответа показать: «Результат неизвестен. Пароль мог измениться. Не повторяй запрос автоматически». Новый сброс — только после нового явного подтверждения. Прежний временный пароль получить через GET нельзя.

Обрабатывать error.code, не выводить сырые ответы в консоль:

| HTTP / code | Действие |
|---|---|
| 400 VALIDATION_ERROR / 415 UNSUPPORTED_MEDIA_TYPE | Сообщить об ошибке запроса; пароль не показан |
| 401 UNAUTHORIZED | Перейти ко входу |
| 403 FORBIDDEN / ACCOUNT_DISABLED | Сообщить об отсутствии доступа, обновить состояние авторизации |
| 403 PASSWORD_CHANGE_REQUIRED | Существующий экран смены пароля администратора |
| 403 INVALID_ORIGIN | Сообщить об ошибке подключения, не повторять автоматически |
| 404 NOT_FOUND | Обновить список: сотрудник отсутствует |
| 409 PASSWORD_CHANGED | Пароль уже изменился параллельно; обновить список, новый сброс только с подтверждением |
| 500 INTERNAL_ERROR | Показать ошибку; автоматического повтора нет |
| 503 SERVICE_UNAVAILABLE | Сервер занят; предложить позднее повторить вручную |

После входа сотрудника использовать существующий механизм: на login/me читать `X-Password-Change-Required: true` и открывать уже готовый экран. `POST /api/v1/auth/change-password` с `{current_password, new_password}` после успеха заменит cookie и вернёт `X-Password-Change-Required: false`. Обращения до этого возвращают 403 PASSWORD_CHANGE_REQUIRED. Логику и экран не дублировать.

Все подписи, подтверждения, предупреждения, ошибки и сообщение об успешном копировании добавить в существующие словари RU/KZ. Проверить обе локали, закрытие окна и очистку секрета, ошибку копирования, двойной клик, потерянный ответ и заблокированный аккаунт. Backend не хранит временный пароль в открытом виде и не предоставляет публичный endpoint восстановления.
