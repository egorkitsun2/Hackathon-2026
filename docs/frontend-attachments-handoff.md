# Шарапат: вложения обращений (API v0.4)

Frontend не изменён. Добавить список вложений в детали обращения и загрузку
только автору, пока status=new. Новые маршруты используют существующие cookie,
роли и один origin. Полный контракт: [api-contract.md](api-contract.md).

## Загрузка

`POST /api/v1/tickets/:id/attachments`, один multipart-файл с полем **file**:

```js
const form = new FormData();
form.append('file', selectedFile);
const response = await fetch(`/api/v1/tickets/${ticketId}/attachments`, {
  method: 'POST', credentials: 'same-origin', body: form,
});
```

Для FormData не ставить Content-Type вручную и не пропускать запрос через
JSON-обёртку, которая добавляет application/json: браузер выставляет boundary.
Если выбрано несколько файлов, отправлять последовательно отдельными запросами,
после каждого обновлять фактический список с сервера. Сервер допускает максимум
3 вложения на обращение, каждый не более 5 * 1024 * 1024 байт. Допустимы
.jpg/.jpeg/.png/.webp/.pdf. UI-проверки дополняют серверные, не заменяют их.

Ответ 201:

```json
{"data":{"id":7,"original_name":"photo.jpg","mime_type":"image/jpeg","size_bytes":123456,"created_at":"2026-11-11T10:00:00.000Z","url":"/api/v1/tickets/124/attachments/7"}}
```

Показывать состояние загрузки, блокировать двойной submit и ограничивать выбор
оставшимся количеством. Не обещать процент, если используется обычный fetch без
прогресс-событий. Прерывание возможно через AbortController; при потере ответа или неопределённой
ошибке сервера запрос мог уже сохраниться: перечитать детали, не повторять POST автоматически.

## Просмотр и скачивание

В `GET /api/v1/tickets/:id` добавлено `data.attachments`: массив этих же метаданных,
по id ASC; для старых/пустых обращений — []. Старые поля не меняются, author
по-прежнему только у admin. Показывать имя, тип, размер и ссылку «Скачать»;
выводить original_name через textContent, не innerHTML. Кнопки удаления нет.

`GET /api/v1/tickets/:id/attachments/:attachmentId` возвращает бинарный файл
автору/admin. Использовать защищённый относительный url с того же origin;
обычная ссылка передаст HttpOnly cookie. Это скачивание, не публичная ссылка
и не JSON API. Для fetch проверить response.ok, только затем читать blob;
при object URL освобождать URL.revokeObjectURL после использования.
Не сохранять файлы, ссылки с токенами или сессионные данные в localStorage.

Загрузку admin в чужое обращение UI не предлагает. У обращения на рассмотрении
или завершённого форма загрузки скрыта, уже сохранённые файлы доступны автору/admin.
При logout/session-ended убрать частные метаданные и игнорировать поздние ответы.

## Ошибки и приёмка

400 VALIDATION_ERROR — пустой/лишний файл, поле, имя или повреждённый multipart;
413 FILE_TOO_LARGE/UPLOAD_TOO_LARGE — размер; 415 UNSUPPORTED_FILE_TYPE —
расширение/содержимое/MIME; 415 UNSUPPORTED_MEDIA_TYPE — неверный формат запроса;
409 ATTACHMENT_LIMIT_REACHED — уже три; 409 ATTACHMENTS_LOCKED — статус изменился,
обновить детали. 401 — повторный вход; 403 PASSWORD_CHANGE_REQUIRED — экран смены
пароля; 403 FORBIDDEN/ACCOUNT_DISABLED — существующая обработка доступа; 404 —
недоступное обращение/вложение; 408 UPLOAD_TIMEOUT, 503 — предложить ручной повтор
после обновления деталей. Сообщения переводить RU/KZ, сырой HTML сервера не выводить.

Проверить: все четыре формата, ровно 5 МиБ/превышение, четвёртый файл, отмену,
потерю ответа и двойное нажатие, изменение статуса во время загрузки, просмотр
автором и admin, запрет чужому сотруднику, reload и старое обращение с [].
Изображения/PDF не декодируются сервером и не проверяются антивирусом; основной
сценарий — защищённое скачивание, не встроенное исполнение документа.
